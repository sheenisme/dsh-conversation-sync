# 界面详解

这是「会话同步」页面的详细说明，简版见 [README](../README.zh-CN.md)。

## 入口位置

面板入口有三处：**设置 → 会话同步**、**左侧边栏的图标**、以及**插件 → 会话同步**。
侧边栏与设置页这两个入口默认都打开，页面顶部各有独立开关
（`入口位置：☑ 左侧边栏 ☑ 设置页`），可以只留常用的那个。

## 两棵树

- **左侧 —— DSH：** 第一级是工作区，第二级是它下面的会话。第一级用工作区而不是
  profile，是因为会话本身不记录自己属于哪个 profile：会话头部没有这个字段，而
  `sessions` 目录是所有 profile 共用的，按 profile 分组只能是猜测。工作区也正是
  DSH 自己侧边栏的分组方式。
- **右侧 —— 机器：** 第一级是机器，第二级是工具，第三级是会话。每台机器会在原地
  显示私钥状态（可直接设置）和发现错误，连不上的主机会自己说明原因，而不是给一个空列表。

**左右各选一个会话**之后按钮才可用——这一对才是工作单元：左侧是要被写入或追加的
DSH 会话，右侧是来源或目标。左侧的 **新建会话** 一行，用于导入 DSH 里从未有过的会话。

两棵树里每一行都能一眼看出状态：**已选中**（强调色描边）、**已绑定**（绿色底加一个
圆点）、**绑定了多个**（`×N` 徽标）。已经绑定的会话**不会消失**——允许把同一个会话
绑到多个来源，这正是「合并对话」的做法。

右侧每个工具分组里还有一行 **在这台机器上新建会话**。放在分组里点它，就等于同时选定了
机器和工具，不会出现不可能的组合；宿主会在该工具自己的目录下建议一个路径
（`~/.claude/projects/dsh-conversation-sync/…` 等），这样下次扫描能发现它。新建的目标
文件还不存在，所以只能接收导出——没有内容可以导入。

## 四个按钮

箭头直接指向文字的去处，按钮不需要猜：

| 按钮 | 作用 |
| --- | --- |
| **← 导入到 DSH** | 把机器上的会话追加进选中的 DSH 会话。不会改动机器上的文件。 |
| **导出到机器 →** | 把 DSH 会话追加进选中的机器文件。不会改动 DSH。 |
| **两边互相补齐** ⇄ | 两个方向都执行，各自补齐对方有、自己没有的内容，重复执行不会重复追加——这就是合并对话的选项。 |
| **较新的覆盖较旧的** ⤵ | 先比对，只把较新的一侧写进较旧的一侧，两侧一致时什么都不做。 |

这四个按钮外面有一圈边框和一行说明，因为它们只作用于上面选中的两个会话，别的都不碰；
左右都选之前一直是禁用状态。

## 同步绑定表

表头有**全选**开关（一次请求完成，连点两下也不会只改一半）、`已勾选/总数` 计数，以及
**同步已勾选**——勾选内容的批量按钮。每行包含：

- 一个短的**绑定 id**（`bnd-1a2b3c4d`）——同一个会话上有两个绑定时，靠它区分，
  出问题时也方便引用；
- **勾选框** —— 只有勾选的绑定才会同步（批量同步、**同步已勾选**都遵守）；
- **方向** —— 新建绑定默认 `两边互相补齐`，也可以选「较新的覆盖较旧的」或固定某一侧；
- **较新一侧** —— 当前判定结果，悬停可看判定理由；
- **立即同步**（只作用于本行）与 **删除**。

目前**故意不提供自动后台同步**：每次同步都会写进别的工具的活跃文件，所以只在你要求时执行。

## 顶部状态条

两棵树上方是一条安静的状态条：一个彩色圆点（绿色就绪、蓝色处理中、失败后变红）、
正在运行的插件**版本**、这个宿主的启动时间，以及最近几行操作记录——每次绑定、
同步、删除都会写一行。版本号比看起来重要：浏览器那一半刷新页面就更新，而宿主
进程要重启应用才换代码，所以版本比已安装的旧，正是新动作报 `unknown action` 的原因。

## 标题与预览

会话文件名是工具自己起的：Claude 用 UUID，Codex 用 rollout 时间戳，所以一列文件名
就是一列字母。因此每一行显示的是会话的**标题**——用户说的第一句话——内部 id 以小字
留在下面，因为绑定真正依赖的是那个 id。标题过长时会在句读处截断并以 `…` 结尾，
不会把词切一半。

鼠标停在某一行上会展开一张卡片：标题、工具、消息数、机器、时间，以及对话**双方**的
前几行内容。这样两个相似的会话在绑定之前就能区分开。

标题在两个方向上都会跟着对话走。DSH 折叠的是最后一条 `session/title` 事件，所以
在 DSH 里改名会被导出；标题以 `dshTitle` 随导出的行一起写出，导入时再还原——包括
会话是第一次被创建的情况。

## 不是每个文件都是对话

Codex 把三种 rollout 写在同一个目录里：

| `thread_source` | 是什么 | 是否显示 |
| --- | --- | --- |
| `user` | 你自己发起的对话 | 显示 |
| `guardian_review` | 对另一个线程的自动评审 | 仅勾选**自动线程**后显示 |
| `subagent` | 由别的会话派生的子代理 | 仅勾选**自动线程**后显示 |

Codex 压缩线程时会把正文换成**加密**的 `compaction` 负载，只留三行：元数据、那个
加密块、设置。这类文件仍会列出，但标记为*无对话内容（已压缩）*，且不可选择——所以
配对不会再在事后报「no importable messages」。机器标题会同时报出两个数字，这就是
可点行数可能少于磁盘文件数的原因。

必要时标题会从文件**深处**读取：Codex 在你打字之前，会把环境、`AGENTS.md` 和自己的
提示写入 `role: "user"` 消息（实测中位数在文件 **153 KB** 处）；另有一个 Claude 会话，
第一句真正的输入在 **1,095,161** 字节处，前面是一兆多的工具输出。扫描只对仍然没有
标题的文件按偏移向更深处探测，而且工具塞进用户位置的那些文本
（`<environment_context>`、`<system-reminder>`、`# AGENTS.md instructions`、
`You are Codex…`…）永远不会被当作名字。

## 哪一侧更新？

写入之前先比较两侧，方向由比较结果推导，而不是假定。比较的基准是**上次同步**，
而不是直接比较两个时间戳，因为这两个数字含义不同：DSH 事件的 `time` 是对话自身的
时间戳（导入一年前的会话就会写入一年前的时间），而文件的 `mtime` 是它落到这块盘上的
时间（复制一下就能让很旧的内容看起来很新）。直接比较会把「刚复制过来的旧文件」永远
判成较新。

改问*这一侧自上次同步后有没有变*，既对称又正确：没有变动的一侧不可能持有另一侧
缺失的内容。记录下来的基准是文件的 mtime 与大小，以及同步成功那一刻 DSH 会话里
最新的事件时间。空的或不存在的来源文件永远不会被判为「较新」——里面没有东西可读，
所以此时应当导出。
